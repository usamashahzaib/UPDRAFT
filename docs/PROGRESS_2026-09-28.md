## Gate B test-runner recovery (2026-09-28, late session)

- **Root causes of the PM/licensing startup failures, both fixed:** (1) a zombie `Unity.Licensing.Client.exe` (PID 2260) survived prior kills because Git Bash mangles Windows `taskkill /PID` switches into a path argument — `powershell Stop-Process` works; (2) a stale `Temp/UnityLockfile` from killed batch runs. After clearing both, a batch launch starts a fresh LicensingClient ("Code 10 ... failed validation; ignoring" is benign — it launches its own client and handshakes), and the Package Manager IPC stream connected in 0.3 s (`Upm-23496`) instead of timing out after 30 s.
- **Fresh recorded evidence:** EditMode **142/142 passed** (0.28 s), PlayMode **6/6 passed** (108.4 s) via `Run-UnityTests.ps1`; XMLs in `TestResults/`. The earlier 5/6 PlayMode run's failure (`PrepBlocksDamageAndPads_LiveFire_DestroysEnemyPads_NotFriendly`: "Friendly fire must not damage a pad. Expected: 60.0 But was: 45.6987") did not reproduce; no combat code was changed in between — the test uses random seeds, so **seed-dependent flakiness in that test is flagged for the gameplay owner to harden** (fix the flaky seed usage, not the pass rate).
- **Compile repairs made to unblock all Unity work** (in-flight Gate E file `PlayerProductScreens.cs`, owner was idle >1h; flagged for owner review): removed an invalid `await` on an `async void` helper and adapted `Action`→`UnityAction` inside `Retry()` — both behavior-preserving.
- **Procedure for future sessions:** confirm no `Unity*` processes (`tasklist | grep -i unity`), delete `ProjectUpdraft/Temp`, run `powershell -ExecutionPolicy Bypass -File Run-UnityTests.ps1 -Platform <EditMode|PlayMode>` — synchronous, no timeout below 10 minutes, never `-quit` with `-runTests`, and never launch while another agent owns the runner.
